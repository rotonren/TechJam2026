## 4. 把学习层单独隔离,在交叉验证下测

对跨会话记忆的顾虑是:它学到的可能是公开集,而不是目录。对照实验把它关掉,
其余一切不变:

```
COMPASSCART_DISABLE_EVOLUTION=1 python -m tools.run_cv --folds 1 2 3 4 --seed 2026
```

| 折 | 开学习 | 关学习 | 差值 |
| ---: | ---: | ---: | ---: |
| 1 | 0.817467 | 0.801905 | **+0.015562** |
| 2 | 0.824997 | 0.818863 | **+0.006134** |
| 3 | 0.769402 | 0.771280 | −0.001878 |
| 4 | 0.836976 | 0.778923 | **+0.058053** |
| **均值** | **0.812211** | **0.792743** | **+0.019468** |
| 标准差 | 0.025676 | 0.018827 | |
| selection | 0.799373 | 0.783329 | +0.016044 |

每折都会新建一个 agent,只看得到 40 个会话,所以记忆层拿到的观测量大约只有
全量运行时的五分之一。**即便如此它仍然值 `+0.019`**,这正好回答了跑交叉验证要问的问题:
这份收益不是靠累积 200 个公开集会话堆出来的假象。

收益具体来自哪里(四折平均):

| | 开学习 | 关学习 | 差值 |
| --- | ---: | ---: | ---: |
| MTTC | 2.831 | 3.300 | **−0.469 轮** |
| MRR | 0.548 | 0.535 | +0.013 |
| Hit@10 | 0.969 | 0.956 | +0.013 |

这一层主要买到的是**轮次**,不是召回 —— 这也正是它被设计出来要做的事。
它纠正的是"该问哪个问题",于是买家的需求更早到达。

第 3 折是值得点名的例外。在那一折上,记忆层省下了 0.575 轮 MTTC(值 `+0.0115`),
却让出了 0.045 的 MRR(值 `-0.0134`),净 `-0.0019`。问一个更容易回答的问题
把需求更早问了出来,但落在了一个略差的排序上。**这一层是四折里赢三折,不是四折全赢**,
报告不该把这一点抹平。

## 6. 实测之后被否决的方案

这些代码都保留在树里、处于禁用状态、带测试 —— 因为它们是上面各项结论的证据:

| 改动 | 差值 | 为什么输了 |
| --- | ---: | --- |
| 窗口内 IDF 加权 | −0.011 | 用窗口自身的统计量去给这个窗口重新打分 |
| ONNX 交叉编码器后端 | −0.007 | 带着第 7 节的窗口混淆,未重测 |
| `relax` 策略 | −0.010 | 卡住并不意味着过滤条件错了 |
| 约束计数式披露信号 | −0.015 | 量的是解析器,不是买家 |
| 分组式模型 prompt | −0.003 | 一个标签写反了,详见 `approach-evolution.md` 第 7 步 |
| 按状态选择 prompt | +0.0002 | 低于噪声;按路由的各自最优不叠加 |
| 分层目录发现 | ±0.000 | 词表完全一致,却要多花 92.7 秒启动 |

## 7. 一次测错了的测量,和它的修正

第一次 LLM 的结果报的是 `-0.001266`。当时模型跑在重排窗口 20 上,而基线跑在 50 上,
并且窗口是阶段级参数而不是按路由的,所以它对短语后端也一起生效了。

```
窗口 50,不接模型      0.822490
窗口 20,不接模型      0.812999    <- 当初缺失的那个对照
```

单是窗口就值 `-0.0095`,而这笔账全算在了模型头上。把窗口改成按路由配置之后,
模型实测为 **`+0.004341`**。

对外报告的是修正后的数字。未修正的那个记录在这里,是因为它的失败模式 ——
一次运行改了两个变量 —— 正是这份文件里其他每一行都配了具名对照的原因。
