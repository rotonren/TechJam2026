What each accepted step did

Starting point, and one measurement before any code

An oracle probe recorded where the target sat at every pipeline stage across 691 turns. The target was in the candidate pool in 99% of sessions and at rank 1 in 32%. Retrieval was not the bottleneck; ordering was. No work went into recall after that.

0.771831

Phrase adjacency

Fusion and constraint scoring both work at term level, so a requirement stated as a contiguous phrase scored no better against a product whose title contains it exactly. The rerank stage supplies that one missing signal.

0.783514

Run it on Browsing only

The same stage measured +0.038 Browsing HitRate and −0.025 Buying. A Buying turn already carries hard constraints, so the ranker is well informed and reordering destroys good work. Turning it off on one route beat every weight and window sweep combined.

0.800849

Question priors that check themselves

The response-likelihood table was hand-written and never validated. Treating it as a prior and updating from whether questions were actually answered corrected the two entries we had backwards — feature from 0.70 to 0.973, budget from 0.90 to 0.000.

Condition the memory on route too

use_case is answered 44% of the time on Buying and never on Browsing. A shopper still exploring has not yet formed a view on what the item is for. Nothing in the code encoded that; it came out of 303 observations.

Spend the turns that were being wasted

When the question policy has nothing worth asking, the turn is spent for nothing — the shopper replies "ask me about one specific attribute" and discloses zero. An open question instead fires eleven times in 536 turns and is worth most of this.

LLM rerank — measured, not shipped

Worth +0.0043 for 362,330 prompt tokens and a 4.3× slower run. Not the default: submission_rules.md forbids shipping API keys and says official scoring may disable network access, so the offline path is what the organizer will actually run. Both numbers are reported.

Three conclusions that were wrong first

Each of these stood for hours and would have gone into the report. The controls that caught them cost about ninety seconds each.

ClaimWhat was actually trueCorrection
The LLM reranker costs score The experiment changed the rerank window and the backend. The window alone cost −0.0095, charged to the model. −0.0013 → +0.0043
Boundary suffered because it routes as Buying and met the model Route counts show Boundary is routed Browsing on all thirty of its turns. The model never ran on it. retracted
Grouping the ledger by role must beat a token bag is_hard=False means this text cannot safely become a filter, not the shopper is indifferent. The prompt called an override's new requirement optional. +0.0025 recovered

The cross-encoder's −0.007 carries the same window confound and has not been re-measured. It is reported as measured, not as settled.

Does any of it generalise?

Every number above was read off the same 200 sessions the changes were tuned on. So one fold of 40 was sealed at the start of the round and opened once, at the end, after the configuration was frozen.

Neither result certifies a +0.004 decision — the tuning folds alone span 0.769 to 0.837, a spread wider than most individual changes in this round. They certify that the +0.0613 of accepted change did not come from memorising the public set. The learning layer is also a net win in three folds of four, not four of four.

The pipeline today

Seven stages per turn. Each is wrapped so a failure degrades rather than breaks the turn. Stages in colour were added this round.

1SessionStoreParse the turn into a versioned constraint ledger. An override supersedes rather than appends.
2PolicyMemoryObserve whether the previous question was answered. This is where cross-session learning happens.
3RoutePlannerBuying or Browsing, from constraint specificity, plus the fusion weights.
4HybridRetrieverLexical, attribute, profile and dense sources fused by weighted reciprocal rank. ~500 candidates.
5ConstraintRankerHard-constraint coverage and quality; exact candidates stay ahead of disclosed relaxations.
6RerankStageRescore the head of the list per route. Browsing: phrase adjacency. Buying: off by default.
7StrategySelectorDecide what to do with a turn the question policy declined — open question, or stop asking.

Switches worth knowing

Turning all three new layers off reproduces 0.761209 exactly, which is how each one's contribution was isolated.

What generalises past this project

Measure the ceiling first

The oracle probe took thirty minutes and decided three days of work. Without it the obvious move was to improve recall, which was already at 99%.

Isolate one variable

Violating this produced a confidently wrong conclusion that survived several hours. The control that caught it was a single ninety-second run.

Adaptation needs real structure

Conditioning on route paid twice, about +0.02 each. Conditioning on "did the last turn fail" lost score in four configurations out of four.

A field's meaning doesn't travel

is_hard means "safe to filter on" in the retrieval path. Read as "important to the shopper" in a new path, it inverted the prompt.

Mislabelled structure beats no structure — downward

A flat query is uninformative. A structured one with the wrong labels is confidently wrong, and cost 0.105 Override MRR.

Layers couple through shared state

Reordering Buying candidates changed what the memory learned, which moved Boundary — a scenario the change never touched. Local optima did not compose.
